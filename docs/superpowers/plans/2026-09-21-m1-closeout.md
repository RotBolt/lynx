# Lynx M1 Closeout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the five remaining M1 gaps so an agent can capture HTTP/1.1, HTTP/2, and WebSocket exchanges, use stable lifecycle/proxy state, and verify the complete Android workflow through structured JSON.

**Architecture:** Keep Lynx-owned `NetworkExchange` models and put protocol handling behind a `ProxyEngine` boundary. The current HTTP/1 parser becomes the compatibility adapter while protocol-specific handlers normalize headers, body bytes, decompression, failures, and frame events into the same evidence store. Android proxy changes remain transactional and session-owned.

**Tech Stack:** Kotlin/JVM 21, Java sockets/SSLEngine, Bouncy Castle, kotlinx-coroutines, JUnit/Kotlin test, ADB.

**Spec:** `lynx-spec/MILESTONES.md`, `lynx-spec/IMPLEMENTATION_TICKETS.md`, `lynx-spec/ARCHITECTURE.md`.

## Global Constraints

- Debuggable Android applications only.
- ADB and the injected/runtime-independent host proxy are the attachment mechanisms.
- macOS is the first host platform.
- Database operations remain read-only.
- No VPN/TUN service and no application code changes.
- Unsupported/bypassed traffic must be reported explicitly.
- Finite responses are versioned JSON; watch output is JSONL.
